# Слой генерации ответов (app/answer) для rag_api

Модуль добавляет к rag_api эндпоинт `POST /answer` поверх извлечения фрагментов.
Он реализует два механизма:

1. Формирование ответа строго из извлечённых фрагментов (схема сборки контекста).
   Генератор размечает каждый фрагмент отметкой CITE или SKIP и объявляет
   `answerable`. При недостатке контекста возвращается отказ с указанием причины,
   что предотвращает галлюцинации.
2. Дополнение недостающего контекста (маршрутизатор). При `answerable=false`
   маршрутизатор формирует уточнённый поисковый запрос и инициирует повторное
   извлечение, исключая уже виденные фрагменты по `seen_chunk_ids`.

Весь код функции лежит в папке `app/answer/`. В остальном rag_api меняются только
три строки в `main.py` (см. ниже), поэтому апстрим `danny-avila/rag_api`
обновляется через `git pull` без конфликтов.

## Интеграция

1. Скопировать папку `app/answer/` в корень rag_api (рядом с `app/`).
2. Внести три строки в `main.py`:

```python
# 1. рядом с прочими импортами роутеров
from app.answer.routes import router as answer_router

# 2. рядом с app.include_router(document_routes.router)
app.include_router(answer_router)

# 3. (опционально) поднять лимит пула потоков для параллельных запросов
# было: int(os.getenv("RAG_THREAD_POOL_SIZE", str(os.cpu_count()))), 8
# стало: ..., 32
```

Если `RAG_ANSWER_ENABLED` не равно `true`, модуль неактивен и на rag_api не влияет.

## Переменные окружения (.env)

Обязательные при включённой функции:

| Переменная | Назначение |
|---|---|
| `RAG_ANSWER_ENABLED=true` | включить модуль |
| `RAG_ANSWER_MODEL` | имя модели генератора и маршрутизатора |
| `RAG_ANSWER_BASE_URL` | OpenAI-совместимый эндпоинт |
| `RAG_ANSWER_API_KEY` | ключ доступа |

Параметры режима (приведены рекомендуемые значения, проверенные на оценке):

| Переменная | Рекомендуемое | По умолчанию | Назначение |
|---|---|---|---|
| `RAG_ANSWER_GENERATE` | `true` | `false` | генерировать текст ответа |
| `RAG_ANSWER_MODE` | `answer` | `schema` | `free`, `schema` или `answer` |
| `RAG_ANSWER_TOP_K` | `20` | `4` | число извлекаемых фрагментов |
| `RAG_ANSWER_MAX_TOKENS` | `8192` | `1024` | лимит токенов ответа (для компрессии нужен запас) |
| `RAG_ANSWER_TEMPERATURE` | `0.0` | `0.0` | температура |
| `RAG_ANSWER_MAX_ITERATIONS` | `2` | `1` | максимум кругов извлечение плюс генерация |
| `RAG_ANSWER_COMPRESS` | `true` | `false` | сжатие процитированных фрагментов между итерациями |
| `RAG_ANSWER_ROUTER_AGENT` | `true` | `false` | маршрутизатор как вызов модели вместо детерминированного |

Секреты и ключи в комплект не входят, задаются в вашем `.env` (он в `.gitignore`).

## Запрос

```
POST /answer
{
  "query": "Какова общая выручка группы МТС за 2024 год в млн руб.?",
  "file_id": "mts_corpus",
  "k": 20,
  "max_iterations": 2,
  "mode": "answer"
}
```

Поля `k`, `max_iterations`, `mode` необязательны и переопределяют значения из `.env`.

Ответ (основные поля):

| Поле | Значение |
|---|---|
| `answer` | текст ответа |
| `answerable` | удалось ли ответить по извлечённым фрагментам |
| `cited` | процитированные фрагменты |
| `retrieved` | все извлечённые фрагменты до сжатия |
| `evidence_assessment` | собранные доказательства |
| `trace` | вход и выход компонентов по итерациям |
| `iterations` | число выполненных кругов |
| `compressed` | применялось ли сжатие |
| `refusal_reason` | причина отказа при `answerable=false` |

## Тесты

```
python -m pytest tests/test_answer.py
```

Покрывают схему сборки контекста, маршрутизатор, режимы генерации и эндпоинт
(на заглушках модели, без обращения к реальному API).
